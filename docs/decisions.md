# 画面の決定の記録

画面の原則（CLAUDE.md）は「なぜ」だけを書く。ここには、その原則をどの画面で・どんな前提で・どの形にしたかを書く（stats2-course #247）。前提が変われば見直してよいのは、こちら。

関係図（まとまりの関係図・2つの概念のページ）の決定は、stats2-course の docs/relation-map-design.md 3 にある。

決定ごとに次を書く：

- **決定**：何をどうするか
- **原則**：どの原則から来たか（CLAUDE.md の番号）
- **前提**：どの画面・どの文脈で成り立つか
- **根拠**：渡辺さんの判断・iPhone の A/B・レビュー
- **日付**
- **見直す条件**：何が変わったら見直すか

## 印

### 印は2種類で、役目を分ける
- **決定**：
  - **分類の印**（確率分布・検定・推定など12種）：島の地図の島の名前、概念の印を取り寄せられないときの点に使う。遠目にどの分類かを見分ける。
  - **概念の印**（全129概念）：入口のライブラリ・概念のページ・地図の点・教科書で、その概念を示し、教科書とつなぐ。
    - 48×48・線 2.4。色は柱の色。分類ごとに形の系統をそろえる（推定は的・確率は円など）。形で描けない概念は記号を主にする。
    - 原本は教材の側（概念の `icon`）。画面は公開のデータの URL を CSS の mask で読む（SVG を本体に入れない。URL は登録した教材の場所の下だけ）。
    - 地図の点は Cytoscape の絵なので mask で塗れず、SVG を取り寄せて currentColor を柱の色に置き換える（src/termIcons.ts）。
    - 縮めたときの分類の見分けは、島の名前と柱の色に任せる。
- **原則**：8・19
- **前提**：教材の概念が129で、教科書と概念をつなぐ役目がある
- **根拠**：渡辺さん 2026-11-05（stats2-course #220。地図の点は「替える」。UI レビュー 18）。前の決定（2026-10-31「129語すべてに別の印は作らない」）は、印が地図の点で分類を見分けるだけだったころのもの
- **見直す条件**：概念の数が大きく増え、印を描き分けられなくなったとき

### 下のタブは印＋短い名前
- **決定**：下のタブだけは、印に短い名前を添えて出す（ほかの所は印を中心にし、名前は長押し・初めての案内）
- **原則**：19・7
- **前提**：下のタブは画面の行き先で、いつも見える
- **根拠**：渡辺さん 2026-10-31（stats2-course #42・#130）
- **見直す条件**：タブの数が増え、名前が入らなくなったとき

## 色

### 柱の色とデータの図の色を混ぜない
- **決定**：柱（記述・確率・推測）は柱の色（tokens の band-1〜3）、データの図はデータの色（data-1〜3）。選んだものの強調は細い輪だけにし、光らせる演出は控えめにする
- **原則**：18・8
- **前提**：柱が3つ、データの系列が3つまで
- **根拠**：stats2-course #224
- **見直す条件**：柱かデータの系列が4つ以上になったとき

## 読むページ

### 全画面のページの骨組み
- **決定**：
  - 中身を読む・つながりを開くときは、実験室と同じ骨組みにする：上に「←・題」、中は指で送る、下に次の1手。
  - ← は1つ前（つながり → 概念 → 地図）へ戻る。
  - 選んだものは色と太さで示す。拡大する・点滅させる動きは使わない。
- **原則**：20・3・10
- **前提**：iPhone の幅。地図の上の面は探すためのもの
- **根拠**：渡辺さん 2026-11-04（stats2-course #188 07・#194）
- **見直す条件**：広い画面（タブレット・PC）で使うとき

### 成立条件は区分ごとに、外れたときの説明と用語の札
- **決定**：
  - 概念のページ・関係のページの「成立条件」は同じ部品（src/Conditions.tsx）。区分のある教材では、要件・仮定・目安・データで確かめる手掛かりの順に見出しを分ける。
  - 見出しの横は区分の意味だけ（定義の条件・保証の条件・近似を勧める基準）。外れたときに何が言えなくなるかは行ごとの「外れたとき」に書く（同じ文を2か所に出さない）。仮定には「保証すること」、目安には対象と出典を添える。
  - 文に出る用語は、行の下に押せる札（44px）で並べ、押すとその概念を開く。押す先のない所では札にせず文字だけ。
  - 区分のない教材は、今までどおり式の条件・データの条件の2つの一覧。
  - 見出しの横の数は区分ごと（要件 1・仮定 1 など）。
  - 保証すること・外れたとき（目安なら対象と出典）が同じ行は1つの枠にまとめ、文を並べる（二項分布の4つの仮定で同じ説明を4回出さない。2026-11-08）。
- **原則**：4・7・6・12・8
- **前提**：教材が成立条件の区分（型の改訂38の conditions_detail）を書いた分類。stats2-course #249 の呼び名
- **根拠**：渡辺さん 2026-11-07・08（stats2-course #249 ①④。式を基準の定義にし、定義と「その分布に従う条件」を分ける）
- **見直す条件**：1つの概念の成立条件が10行を超え、区分の中でたたむ必要が出たとき

### 関係のタブの見出しは呼び名と向きで分ける
- **決定**：概念のページの関係のタブは、定義に使う概念・前提知識・前提・変換・対比・これを定義に使う概念・応用の見出しに分ける（使われる側のページは「これを定義に使う概念」）。見出しが種類を言っている行には札を重ねない。つながりの地図（RelMap）は4つの側のまま、側の名前は見出しの名前をつなげて出す
- **原則**：4・8・7
- **前提**：型の種類の名前（材料・前提）は v2 まで変えず、画面の言葉（src/kinds.tsx の kindName）だけを新しくする
- **根拠**：渡辺さん 2026-11-07（stats2-course #249 ④）
- **見直す条件**：つながりの地図を、関係の種類ごとの置き場所で描き直すとき（#249 のあと。渡辺さん 2026-11-07）

## 動き

### 使う動き
- **決定**：
  - 縁から出入りする物（上の帯・下のタブ・下の面）は、その縁の方へ滑りながら薄く・濃くする（--dur-sheet・--ease-sheet。math-lab の base.css の data-edge）。
  - 押すと少し沈む。タブを替えると中身がすっと出る。予測の結果は一度だけ光らせる。
  - 拡大・点滅は使わない。
- **原則**：10・16
- **前提**：iPhone の Safari。動きを減らす設定では止める
- **根拠**：渡辺さん 2026-11-07（縁の動きをそろえる）。stats2-course の「見た目と手触り」（#42）。予測の結果を光らせるとき、iPhone では軽く振動させる（試み）
- **見直す条件**：動きが何を伝えているか分からないと分かったとき

### 長押しの手触り：沈んで光る
- **決定**：
  - 長押しのある所は全部、押さえている間に同じ手触りを出す：押した物がゆっくり沈み（0.92 倍まで）、縁が主の色で光っていく。満ちたところ（--dur-hold、450ms）で長押しが決まり、軽く振動する。途中で離すとふつうの「押した」。
  - ふつうのタップの間は見えないよう、押した返事（--dur-press）のあとから始める。指を動かしたら（地図を動かす）やめる。
  - 線は沈まず、太くなりながら光る。島の地図の点（Cytoscape）は、点の枠が主の色で太くなる。
  - 仕組みは math-lab の base.css の `data-hold`（見た目の物が子のときは `data-hold-part`）。新しく長押しを足すときも、これを付ける（tests/e2e/hold.spec.ts）。
  - 動きを減らす設定では沈まず、満ちたときに縁を一度灯すだけ。
- **原則**：10・13
- **前提**：長押しは見えない操作で、押さえている間に「長押しになる」と分からないと、離してよいか迷う
- **根拠**：渡辺さん 2026-11-07（戻るの長押しの見本 https://claude.ai/artifact/N4NgvkERR9KnRSJ5E9K5M4 で「3 沈んで光る」。「その他の長押しエフェクトにも統一が必要」）
- **見直す条件**：長押しの長さが合わない（早すぎて誤って出る・遅すぎて待たされる）と分かったとき

### 指の物理の値
- **決定**：
  - 遊び 8px を越えたら指の真下に付く。
  - 投げは1本指の直近 100ms の速さで。2本指のあとは流さない。
  - 縁は重くなり、離すと縁ぴったりに戻る。
  - 狭い高さ・埋め込みでは、全画面のページで開き、上に「‹」を置く。
- **原則**：2
- **前提**：iPhone の指。埋め込み（360×320）
- **根拠**：渡辺さん 2026-11-06（stats2-course #239 の UX レビュー）
- **見直す条件**：実機で指に付いてこない・流れすぎると分かったとき

- **原則**：守ること 6（個人の記録を扱わない）
- **前提**：公開サイトには秘密の鍵を置けない
- **根拠**：渡辺さん 2026-11-02（stats2-course #57・#54 は保留）
