# 知識ネットワーク（knowledge-net）：計画

KSLP 企画・基本設計書 Ver.1.0（2026-10-28）の第1〜2段階（知識データモデル・静的Webアプリ MVP）。
教材に依らない土台として作り、統計検定2級（stats2）を最初の教材としてつなぐ。2026-10-29 に合意。
2026-10-29 にリポジトリ knowledge-net を作り、stats2-course の docs/knowledge-net/ から移した。型の元はこのリポジトリの `schema/`。

## 役割の分け方

| リポジトリ | 持つもの |
| --- | --- |
| knowledge-net（公開） | 画面・データの型（版つき）・教材の一覧（どの教材のデータをどこから読むか）・テスト・公開サイト |
| 教材のリポジトリ（stats2-course など） | 概念・関係・導出の原本。build が型どおりか検査し、ネットワーク用の JSON を書き出す |
| 教材の公開サイト（stats2-labs など） | 書き出した JSON を公開する |

- 画面は教材の原本を直接読まない。公開された JSON だけを読む。
- 別の教材も、同じ型で JSON を書き出して一覧に1行足せばつながる。

## 型と版

- データの型は knowledge-net で1か所だけ管理し、版番号を付ける（`kn-schema` v1, v2 …）。
- 教材の側はその版の写しを持ち、build で検査する。写しが元とずれたらテストで止める（リポジトリを作るまでは、この写しが元）。
- 画面は、読み込むデータの型と版を確かめ、合わなければ表示せずに知らせる。

## 教材をまたぐ ID

- ネットワークの中の ID は `教材名:教材の中のID`（例：`stats2:TERM-perm`）。教材の中の ID は変えない。
- 関係は別の教材の概念も指せる（例：`stats2:TERM-ratio` → `math:…`）。指した先がまだ無い関係は、画面で「未接続」と表示する。

## 型 v1（2026-10-29 決定、#41）

型のファイル：`docs/knowledge-net/schema/kn-schema-v1.json`（JSON Schema 2020-12）、関係の種類：`relation-types.yaml`。書き出し例：stats2-course の `out/site/net/stats2.json`。

| 種類 | 項目 |
| --- | --- |
| 概念 | id・名前・英語名・版・定義・原理・成立条件（数学的な条件／データに当てはめる条件）・具体例・反例・式（記号の意味つき）・よくある誤解・出典・単元・問題 |
| 関係 | id・版・起点・終点・種類・説明・成立条件・前提の種類（理解／数学）・変換の仕方（厳密／近似／極限）・単元 |
| 導出 | id・版・前提・結論・言えること・手順・成立条件・単元 |
| 教材 | 教材名・題名・単元の一覧（id・題名・ページの URL） |

決めたこと：
- 「前提をさかのぼる」でたどるのは、前提・導出・一般化・特殊化・統合だけ（2026-10-29）。変換・対比・応用はたどらない。二項分布→正規分布（近似）のように、変換は学ぶ順ではないため。学ぶ順に要るものは「前提」の関係で別に書く。
- 関係は KSLP の8種類を維持し、種類ごとに定義・矢印の読み方・該当例・該当しない例を決める。変換は厳密・近似・極限を区別し、前提は理解に必要な知識か数学的な成立条件かを明記する。一般化と特殊化は片方だけ書く。前提が2つ以上の導出は点にする。
- 概念の成立条件は、数学的な条件と、現実のデータに当てはめるときの条件に分ける（正規分布の「左右対称な山1つ」は後者の手掛かり）。
- 版は概念・関係・導出に持たせる（個人の記録がどの版で学んだかを指せるように）。
- 後で足す任意の項目（型を壊さない）：対比の共通点・相違点（#52）、概念から図・ラボへのリンク（W0c）、別名（検索を作るとき）。
- 5つの能力の評価の観点は、KSLP の評価基準（Rubric）として別のデータにする（#54）。

W0a：U13〜U16 の8概念（確率変数・期待値・分散・独立・二項分布・ポアソン分布・正規分布・標準化）、関係10、導出2 で検査が通った。説明のまだない概念（中心極限定理）は status: stub で書き出す。

## 技術

| 用途 | 採用 | 理由 |
| --- | --- | --- |
| 画面 | React＋TypeScript＋Vite | KSLP の残りの画面（概念比較・再構築演習）まで同じ土台で作れる |
| ネットワーク | Cytoscape.js | 点と線の配置、拡大・移動、前提をさかのぼる表示 |
| 数式 | KaTeX | 概念の式の表示 |
| データの検査 | 画面側は Ajv、教材側は build（Python） | どちらも同じ JSON Schema をそのまま使う（Zod で書き写すと型が2か所になるので、計画の Zod から変えた） |
| テスト | Vitest＋Playwright | |
| 公開 | knowledge-net の GitHub Pages | Notion に埋め込む（スマホで拡大・移動できる） |

後回し：Tailwind・shadcn/ui（見た目は今のラボの書き方に揃える）、Plotly・math.js（数理ラボの段階で必要になってから）。

## リポジトリを作る時期（条件）

次の2つが揃ったら `knowledge-net` を作り、このフォルダと型を移して画面を作り始める（W0b）。

1. 型 v1（概念・関係・導出の項目、関係の種類、教材をまたぐ ID の付け方）が決まっている。
2. W0a の5〜8概念を型 v1 で書き、stats2-course の build で検査が通っている。

## 画面の最初の版（W0b）で作るもの

KSLP 第12章の MVP から：概念と関係の表示、前提をさかのぼる表示、2〜3概念の比較、教材の単元へのリンク。Notion の埋め込み（高さ約320px）では小さい表示にし、「大きく開く」で全画面にする。
