# 統計検定教材 UI レビュー

2026-11-04 · 渡辺正雄（Claude と作成。元は Claude の文書「統計検定教材 UI レビュー」）

土台の作り込みは丁寧で、横のはみ出しはどの画面にもない。直すべきは「押せる大きさ」「動線の行き止まり」「同じ情報の重複」「今日決めた動きの方針と実装のずれ」の4つ。

## 確認した範囲

- 対象：knowledge-net の main（#105 のマージ後、2026-11-04 23:20 時点）
- 画面：地図、概念のシートと全画面ページ（概要・式・関係）、関係のページ、実験室の一覧、問い A-01 の作業台、Notion 埋め込み
- 幅と配色：390×844（iPhone 相当）のライトとダーク、埋め込みは 360×320
- データ：リポジトリの見本（public/sample）。教材側の図とラボの画像は読み込んでいない
- 方法：実際に描画して画面を撮り、押せる範囲の寸法とCSSの値（tokens・動き）も確かめた

## 良い工夫（残したい所）

画面の決まりを文章で決め、CSSと検査の仕組みで守らせている点が、この教材のいちばんの強みになっている。

**情報の並べ方**

- 概要が「問い → つまり → 図 → 定義」の順になっている。定義から始めず問いから入るので、「予測する・考える」という在り方に合う
- 原理・条件・例と反例は、たたんだ行で「開いて読む段」に置いている。最初の画面が詰まらない
- 式の作業台で、式のかたまり（ₙCₖ・pᵏ・(1−p)ⁿ⁻ᵏ）を色の帯で分け、押すと意味と今の値が出る。式を「読む」体験になっている
- 計算の段を 1／4 で送れる。結果は 26.68% と 0.26683 の両方を出し、割合と確率の両方の読み方に対応している
- 実験室の予測では、予測を選ぶまで次へ進むボタン（まず予測を選ぶ）を押せない。予測してから確かめる順を、画面の側で守らせている
- 作成中の問い（A-04）を点線と「作成中」の札で残し、全体の中での位置を見せている

**作りの丁寧さ**

- 色・動きの長さはすべて変数（tokens）で、`npm run design` が直書きの色・決まった長さ以外の動き・ずっと動く飾りを止める
- ライトとダークの両方で色を組み、ダークの地図も読める明るさを保っている
- 動きを減らす設定（prefers-reduced-motion）に、地図・ページ・シート・実験の部品の多くが応じている
- 全画面の面は iPhone の切り欠き（safe-area）の分を空けている
- 選んだ概念を URL（`c=`）に持つので、共有や Notion からの直リンクがそのまま効く
- 埋め込み（360×320）では地図と1行の説明と「拡大表示」だけに絞り、狭い枠に収まっている
- 「線の見方」で凡例をたたんで置き、地図の上を占めない

## 動線設計

「地図 → 概念 → 実験室」の本筋は通っているが、関係のページと実験室への移り目で流れが切れる。

1. **関係のページが行き止まり**：下に「次の1手」がなく、画面の下の約3分の2が空白になる。「組合せ へ／二項分布 へ」の2つのボタンでは、どちらが戻る操作でどちらが進む操作か分からない。下に「この関係を実験室で確かめる」（関係につながる問い、例：A-03）を1つ置き、2つの概念は名前の行として上に寄せる
2. **実験室に移ると ← が消える**：概念のページの「実験室で検証」から移ると、上が「知識ネットワーク」の見出しに戻り、下のタブも「実験室」に変わる。来た概念に戻る手段が下のタブしかない。概念から入った時は、一覧の上にも「← 二項分布」を出す
3. **一覧と作業台で問いの文が違う**：一覧の A-01 は「成功確率を変えると分布はどう動く？」、作業台は「成功確率を上げると、成功回数の山はどう動く？」。押した後に別の問いに見えるので、どちらかに揃える
4. **関係タブの説明が古い**：「押すと、下から説明が開く」と書いてあるが、実際は全画面のページに移る（2026-11-04 の決まりの通り）。文言を直し、各行の右に › を付けて押せることを見せる
5. **最初の地図に入口がない**（→ 分類のライブラリを入口にして試作で対応。下の「地図の変更で見直した点」）：初めて開いた人には、地図・検索・下のタブのどこから始めればよいかが示されていない。地図の下の空き（画面の約半分）に「はじめの1歩：二項分布から」のような入口を1つ置く
6. **ID と記号の意味が説明されていない**：「U14 U15 U19」、問いの「A-01」、A〜F の分け方、下のタブのバッジ（U14・1・17）。初めての時の案内か長押しで意味を出す（決まりの「印と説明を分ける」に沿う）

## 使い勝手

いちばん急ぐのは押せる範囲で、決まりの 44×44 を下回る所が実験室と地図の周りにある。

**押せる範囲（44×44 未満）**

| 場所 | 今の大きさ |
| --- | --- |
| 実験室の ← と ⓘ | 36×36 |
| 実験室の段の印（予測〜応用） | 72×42 |
| 予測の −／＋ | 42×42 |
| 見方の切り替え・絞り込みの札（App.module.css の .mode・.chipBtn） | 高さ 30 |
| 分類の選択（.groupSel） | 高さ 36 |

見た目は小さいままでよいので、押せる範囲だけを広げる（余白か疑似要素で）。

**操作と入力**

- **予測の入力**：−／＋ で頂点を動かし「選ぶ」を確かめる方式は、手数が多く、何を選んでいるかが見えにくい。すぐ上の表の行（0回〜10回）を直接押して選ぶ形にし、−／＋ は補助に回す
- **式タブで同じ値が3か所に出る**：n・p・k の行、スライダー、下のチップ（n 10・p 0.3・k 3）。「同じ機能を2か所に置かない」に反する。行を押すとその場でスライダーが開く形にまとめる
- **「実験する 1回／100回」が選択式に見える**：100回が選んだ色になり、押すと実験が走るのか、回数を選ぶだけなのかが分からない。行動なら2つのボタンにする
- **「種 54972」「記録を削除」**：乱数の種は学習者には意味が分からない。「記録を削除」は薄く小さいうえ、確認なしで消える恐れがある。どちらもメニュー（…）へ移し、削除には確認を入れる
- **式タブの「Y＝aX＋b」**：二項分布の作業台に、説明なしで一次変換が現れる。作業台の型で固定の欄なら、「期待値の性質を試す」と見出しで目的を書く

**重複と量**

- 実験室の一覧は二項分布で絞っているのに、全行に「主：二項分布」が出る。絞った概念と同じ時は省き、「関連：組合せ」だけを残す
- 関係タブで、見出し「対比」の下の行すべてに札「対比」が付く。見出しと同じ札は省く
- 地図の見方（フォーカス／経路／俯瞰）・面（概要／式／関係）・式の読み方（意味／構造／計算）の3段が同じ見た目の切り替えで、階層の違いが見えない（レイアウトの節で扱う）

## レイアウト

骨組みは揃っているが、最初の地図の使い方と、切り替えが3段重なる所が弱い。

- **最初の地図が小さい**（→ 入口をライブラリに替えて試作で対応）：地図の枠は高さ約 440px で、点の文字は約 8px と読めない。枠の下の約半分は空白になる。最初は枠を画面の残りいっぱいに広げ、点の名前が読める倍率（決まりの「印＋名前」の段）から始める
- **切り替えの3段に差を付ける**：いちばん上（地図の見方）は今の囲みの切り替え、面（概要／式／関係）はタブらしい下線付き、式の読み方（意味／構造／計算）は小さな札、と形で階層を分ける
- **実験室の表で数値がはみ出す**：「0.0977%」が枠の右の余白に食い込み、24.6% などと右端が揃っていない。数値の列を等幅数字（font-variant-numeric: tabular-nums）で右揃えにし、列の幅を最も長い値に合わせる
- **関係のページの下の空白**：本文は上の約3分の1で終わる。動線の節の「次の1手」を下に固定して置けば、空白も埋まる
- **見出しの重複**：シートの段では、地図の上の「二項分布」とシートの「二項分布」が同時に見える。シートが開いている間は地図の上の題をたたむ
- **字の大きさの直書き**：App.module.css などに 13px・12.5px・14px が直接書かれ、--fs-* の変数を使っていない。色と同じく、`npm run design` で止める対象に足す
- **実験室の一覧の最後の行**：下のタブ（約 60px）に最後の行が隠れないよう、下の余白をタブの高さと safe-area の分だけ取っているか確かめる

## カラー設定

色は変数で一元管理できているが、同じ意味の色が画面によって違う所と、意味の違う色が同じ系統に寄っている所がある。

| 色の変数（ライト） | 今の使い道 | 気になる点 |
| --- | --- | --- |
| --accent #0f7f73（緑青） | 選んだ見方・主の行動・中心の概念 | 主の行動（実験室で検証）に限っており良い |
| --data-1 #2a78d6（青） | 実験室の表の棒 | 概要の図は --data-1-soft #9dbfe8（淡い青）で、同じ分布の色が違う |
| --data-hi #b86e00（琥珀） | 最も起こりやすい値の強調 | 押した所を示す --focus #b58000 とほぼ同じ色で、「強調」と「選択中」が見分けにくい |
| 絵文字の色（🧪 など） | 「図・解説・操作」の札 | 変数の外の色が入り、「色は意味のある所だけ」から外れる |

- **同じ分布は同じ色に**：概要の図も実験室も --data-1 の濃い青に揃え、淡い青は「理論」と「実験」を並べる時の片方に限る
- **強調と選択を分ける**：--focus を --accent 系に寄せるか、--data-hi を赤みの少ない色に変え、2つの琥珀色を離す
- **絵文字をやめる**：「🖼 図 4・▶ 解説・🧪 操作」は、下のタブと同じ線の印に揃える
- **地図の線の色**：導出・近似・極限・対比が青・琥珀・赤紫・灰の4系統で、色だけで種類を分けている。点線・破線の違いも付いているが、色覚の違いへの配慮として「線の見方」を開かなくても線の名前が分かる工夫（選んだ線の上に短い名前を出す）があるとよい
- **ダーク**：地図と画面の読みやすさは保たれている。ダークの --data-hi #c98500 と --focus #e0b04a も近いので、上と同じ扱いにする

## エフェクト・動き

今日（2026-11-04）の「すべらせる・拡大する・点滅させる動きは使わない」という決まりに対し、実装には跳ねる動きと拡大の動きが残っている。

- **跳ねる動き（--ease-bounce）**：値が一度 1.046 まで行き過ぎて戻る曲線。メニューの項目（Detail.module.css）と、下のタブ・ボタン（Shell.module.css）の押した時の動きに使われている。押した時は --ease の短い動き（--dur-press 90ms）に置き換える
- **ばね（--ease-spring）の 480ms**：メニュー、経路の開閉（PathList）、地図の説明（Graph）、全画面の地図、下のシートに使われている。シートを指で引いて離す所はばねが自然だが、ほかは 200ms（--dur）で十分
- **拡大の動き**：メニューは 94% から、全画面の地図は 98% から大きくなって現れる（@keyframes pop・bigIn）。不透明度だけの切り替えにする
- **結果を光らせる（--dur-flash 700ms）**：計算結果が出た所を一度だけ淡く光らせる。点滅ではないので残してよいが、続けて何度も値を動かすと光り続けて見えるので、連続で操作している間は光らせない
- **検査に足す**：`npm run design` は動きの長さが変数かどうかだけを見ている。--ease-bounce と scale の @keyframes も止める対象に足すと、決まりから外れた動きが戻らない
- **動きを減らす設定**：対応している部品は多いが、math-lab の BottomSheet.module.css には対応がなく、下からせり上がる動きがそのまま走る

## 用語・文章

統計検定の用語に揃える方針（2026-11-04）に対し、同じものを2つの言葉で呼ぶ所が残っている。

| 場所 | 今の言葉 | 揃える案 |
| --- | --- | --- |
| 概要の「つまり」 | 当たる確率・当たった回数 | 成功確率・成功の回数（定義と作業台に合わせる）。「つまり」の言いやすさを残すなら「成功（当たり）」と1度だけ添える |
| 実験室の段の名前 | 理由 | 考察（在り方の「考える」と漢語の見出しの方針に合わせる） |
| 問いの題 | 一覧「成功確率を変えると…」／作業台「成功確率を上げると…」 | どちらか一方に揃える |
| 実験室の一覧 | 主：stats2:REL-samplingerror-se-contrast（C-01） | 内部の ID がそのまま出ている。関係の名前（例：標本誤差と標準誤差の対比）に置き換え、名前がない時は出さない |
| 関係のページ | 数学的な成立条件・定義に使う | 札の形だが押せない。押せる札と形を分け、ただの文として置く |
| 式タブ | 種 54972 | 学習者には出さない（メニューへ） |
| 関係タブの注記 | 押すと、下から説明（図・解説・操作）が開く | 押すと、関係のページが開く |

- 画面の文章は常体の決まり通りで揃っている。図の説明（「いちばん起こりやすいのは 3 回。平均 np＝3 回の近くに山ができる」）は短く、図を読む手がかりとして良い
- 図の軸に名前がない（横軸「成功の回数 k」、縦軸「確率」）。概要の図にも軸の名前を付けると、作業台の図との対応が分かる

## 導入したい技術

今の構成（React 19・Vite・Cytoscape・KaTeX・Radix・Playwright）は変えず、検査の自動化と表示の速さを足すのが効果が大きい。新しい枠組みへの乗り換えは勧めない。

| 技術 | 解決すること | 手間 |
| --- | --- | --- |
| Playwright の画面比較（toHaveScreenshot、追加の導入なし） | 390px・ダーク・埋め込みの見た目の崩れを PR で止める。今は「スクリーンショットも見る」が人の目に頼っている | 小 |
| 押せる範囲の検査（Playwright の中で全部のボタンの大きさを測る、自作） | 44×44 未満を自動で止める。今回見つかった 36px・42px の所はこれで防げた | 小 |
| @axe-core/playwright | 文字と背景の対比、名前のないボタン、見出しの順を検査する。ライトとダークの両方で走らせる | 小 |
| Vite の分割読み込み（import() と build の分け方の設定） | 今は JavaScript が 1 つの 1.6MB（圧縮後 約 495KB）。Cytoscape は地図、KaTeX は式、実験の部品は実験室を開いた時に読む形にすると、iPhone と Notion の埋め込みで最初の表示が速くなる | 中 |
| View Transitions API（ブラウザの機能） | 地図 → 概念 → 関係の全画面ページの移り目を、不透明度の切り替えだけで滑らかにつなぐ。動きを控える方針と両立し、動きを減らす設定の時は切れる | 中 |
| PWA（vite-plugin-pwa） | ホーム画面に置け、電波の弱い所でも開ける。サイトは公開データだけなので、個人の記録を扱わない決まりとも合う | 中 |
| Stylelint（決まりを書いた設定） | 字の大きさの直書きや scale の動きなど、今の check-design.mjs の正規表現では拾いにくい決まりを CSS の文法で確かめる | 小 |
| Lighthouse CI | 表示の速さと読み込む量に上限を決め、上回ったら PR で止める | 中 |

- 順番は、検査の3つ（画面比較・押せる範囲・axe）→ 分割読み込み → 画面の移り方 → PWA が無理がない。検査を先に入れると、後の変更で崩れた所がすぐ分かる
- テストの決まり（最小十分性）に沿い、画面比較は主な画面の数枚に絞る。全画面を撮ると保守の手間が増える

## 高品質な UI の技術の入れ場所

どれも部品と値は math-lab に置き、画面（src/）は使うだけにする。決まり（#107）の通り、math-lab で1度作れば全部の画面に効く。

**1. 日本語の改行（BudouX）**

- 置き場所：math-lab/packages/ui/src/ に新しい部品 `Phrase.tsx` を作り、index.ts から出す
- 中身：BudouX の日本語の分け方で文を文節に分け、文節の間に `<wbr>` を入れて返す。CSS は `word-break: keep-all; overflow-wrap: anywhere;`（長い英字の語だけは途中で折れるように）
- 使う所：Detail.tsx の問い（concept-question）と題、Scene.tsx の「今回の問い」、実験室の一覧の問いの行、Relation.tsx の題（「組合せ は 二項分布 の前提」）
- 教材の JSON は画面を開いた時に読むので、分けるのもその時に行う。同じ文は覚えておき、2度目からは分けない

**2. 見出しの組み方**

- 置き場所：math-lab/packages/ui/src/base.css の h1・h2（6〜7行目）
- 中身：`text-wrap: balance;` と `font-feature-settings: "palt";` を足す。本文の p には `text-wrap: pretty;` だけ足す

**3. 画面の高さ（dvh と visualViewport）**

| ファイル | 今 | 変える |
| --- | --- | --- |
| src/Graph.module.css の .graph | height: 56vh | 56dvh |
| src/App.module.css の .embed | height: 100vh | 100dvh |
| src/App.module.css の .withSheet | padding-bottom: 55vh | 55dvh |
| math-lab の Experiment.module.css（.pkPanel・.walkSheet） | 70vh・42vh | 70dvh・42dvh |
| src/App.tsx（100行目）、src/Detail.tsx（112行目）、src/Graph.tsx（169行目）、math-lab の Sheet.tsx（12行目） | window.innerHeight | 共通の関数（math-lab の motion.ts の隣に viewport.ts）にまとめ、visualViewport.height を使い resize で読み直す |

キーボードが出た時やアドレスバーが縮んだ時に、下のボタン（実験室で検証・まず予測を選ぶ）が隠れたり、シートの段がずれたりするのを防ぐ。

**4. 枠の幅で形を変える（コンテナークエリ）**

- 置き場所：math-lab の Workspace.module.css の作業台のいちばん外の枠に `container-type: inline-size;`
- 中身：`@container (width < 340px)` の時、n・p・k のチップを2列に、計算の段の式を2行に折る。シートの段（幅いっぱい）と全画面のページで同じ部品が自然に収まる
- 同じ形を App.module.css の .embedCard（埋め込み）と、実験室の一覧の行にも使う

**5. 画面の移り方（View Transitions）**

- 置き場所：math-lab の motion.ts に関数 `changeView(fn)` を足す。中で `document.startViewTransition` があり、動きを減らす設定でない時だけ `flushSync(fn)` を包む。ない時は fn をそのまま呼ぶ

## 地図（俯瞰）の改善と見せ方の案

俯瞰の弱点は「縮めると何も読めない」「どこにつながるか画面の外が分からない」の2つ。縮めた時は語ではなく分類の島を見せ、読む倍率では選んだ概念の周りだけを濃くするのが効く。

**今の俯瞰で起きていること**（見本のデータ、390px で確かめた）

- 19語の全体図は倍率 0.30 で収まり、「印だけ」の段になる。分類の印がない語は白い四角だけが並び、名前も分類も分からない
- 分類の地図（12分類）は3列の格子に順に置いている（Graph.tsx 161行目、横 170・縦 120 ずつ）。学ぶ順の向きと置き場所が関係なく、線が多く交わる。線の太さ（本数 w）も読み取れない
- 概念を選んで俯瞰にすると、倍率 0.9 で選んだ概念を真ん中に出す（READ_ZOOM の工夫）。名前は読めるが、画面の外へ出る線の行き先が分からない。全画面でも左右の語（期待値・分散）が切れる
- 二項分布とポアソン分布の間のように同じ2つの語を結ぶ線が2本あると、線の名前（対比・変換）が重なり「対比変換」と読める

**改善策と入れ場所**

1. **縮めた時は分類の島にする（意味で縮める）**：Cytoscape の親子の点（compound nodes、追加の導入なし）で、語を分類の親の中に入れる。Graph.tsx の elementsOf（71行目）で各語に `parent: cat:分類` を付け、applyLod（177〜187行目）で、far の段は子の名前を消して親の名前（例：確率分布 13語）を大きく出す。今の「印だけ」の段がそのまま「分類の島」の段になる
2. **分類の地図を学ぶ順に並べる**：161行目の格子をやめ、分類どうしの線に dagre（すでに使っている）を当てて上から下へ並べる。線の太さを本数に比例させ、押した分類につながる線だけを濃く、ほかは薄くする
3. **選んだ概念の周りを濃く、ほかを薄く**：俯瞰でも、選んだ語から2歩以内の語と線は今の濃さ、それ以外は不透明度 0.25 にする。全体の形は見えたまま、読むべき所だけが浮く（隠すのではなく薄くするので、地図の全体は失わない）
4. **同じ2語の線をまとめる**：elementsOf（75行目）で、同じ2語を結ぶ関係を1本にまとめ、名前を「対比・変換」とする。押すと関係のページで2つを並べて見せる
5. **画面の外の行き先を枠の縁に出す**：選んだ語につながる語が画面の外にある時、枠の縁にその方向の小さな札（例：← 期待値）を出し、押すとそこへ移る。Graph.tsx の pan・zoom の時の処理（198行目の札と同じ仕組み）に足す
6. **最初の倍率**：全体図を開いた時も、選んだ語がなければ「名前だけ」の段（倍率 0.55）を下回らない倍率で始め、指で縮めると島の段へ移る

| --- | --- | --- | --- |

## 地図の変更で見直した点（2026-11-05）

入口をライブラリに、分類を開いた所を「その分類だけの地図」に替えたことで、レビューの前提が3つ変わった。見方の切り替え・色の意味・枠の形を、新しい地図に合わせて決め直す。

**レビューの前提が変わった所**

| 項目 | 前の見立て | 変わったこと |

| 最初の画面 | 小さな地図で、入口がない（動線5・レイアウト1） | 分類のライブラリが入口になり、文字が最初から読める。この2点は解消 |

**決め直したいこと**

1. **見方の切り替えの意味**：「俯瞰」は全体の入口（ライブラリ）と「全部の語」の島の地図の2つと重なる。上の見出しの役割（上＝探す・分類）に合わせ、ライブラリ → 分類の地図 → 語のフォーカス、の3段をパンくずで示し、切り替えは「フォーカス／経路」の2つに減らす案がある。使われなくなった分類の地図（overview）のコードは消す
2. **柱の色は専用の変数に**：ライブラリと島の地図の柱の色（記述・確率・推測）に、データの図の色（--data-1〜3）を流用している。そのため、二項分布の図の青と「データを記述する」の青が同じになり、「確率分布の語なのに図は記述の色」に見える。tokens に柱の色（例：--band-describe・--band-prob・--band-infer）を足し、図の色と分ける。「色は意味のある所だけ」の決まりにも、柱の色を意味のある色として書き足す
3. **枠の形をそろえる**：ライブラリでは、タイル（角丸24）・語の枠（角丸16）・上の縁だけ柱の色の線、と枠の形を決めた。概念のページの「つまり・図・定義」のカード（--r-l）と実験室の一覧の行にも同じ縁の線を使うと、ライブラリから概念へ移った時に同じ教材の画面だと分かる。角丸は3段（大・中・小）までに決め、tokens にする
3a. **カードを1つの部品とトークンにまとめる**（3の具体化）：今は、概念のページの定義・つまり・図（Detail.module.css の `.block`・`.more2`・`.mini`）、実験室の一覧のカード、ライブラリのタイルが、それぞれ CSS を手で書いている。math-lab の `Card`（Layout.tsx）は画面で3か所しか使われず、同じ名前の別の部品（ExperimentQuestion.tsx の `Card`）もある。角丸も tokens（4・6・10px）とライブラリの直書き（24・16px）で食い違う。そこで次のように決める
    - **トークン**（math-lab の tokens.json）：カードの角丸（`--r-card`）・タイルの角丸（`--r-tile`）・カードの内側の余白（`--card-pad`）と中の間隔（`--card-gap`）・カードの枠の線（`--card-line`）・上の縁の線の濃さ（`--card-edge`）・柱の色（2の `--band-*`）
    - **部品**（math-lab の `Card` を広げる）：見出しの札（例：定義・二項分布 実験室）・題・本文・下の行（例：実験室を開く・stats2:TERM-anova・版 1）を決まった場所に置く。柱を渡すと上の縁だけ柱の色になる。押せるカード（a か button）は右に › を出し、押せる範囲は 44px 以上。ExperimentQuestion.tsx の `Card` は別の名前（問いの欄）に変える
    - **置き換え**：概念のページのカード・定義だけの概念のカード・実験室の一覧のカード・ライブラリのタイルを、この部品に置き換える。同じ見た目のカードを画面ごとに書かない
    - **検査**：`npm run design` で、src/ の border-radius と box-shadow の枠を tokens（`var(--r-*)`・`var(--card-*)`）だけにする
4. **地図の点の印を語の印に**：地図の点は今も分類ごとの共通の印。語の印（129語）を地図の点にも使うと、決まりの「印だけ」の段でも語を見分けられ、ライブラリと地図で同じ印になる
5. **間隔は tokens だけで**：ライブラリの CSS にはタイルの内側の 10px・枠の間の 8px が直書きで残っている。--sp-* に寄せ、`npm run design` で間隔の直書きも止める
6. **同じ機能を2か所に置かない**：最初の試作では、分類の名前と4つ目の枠（ほかの語）の両方が「その分類の地図を開く」だった。名前は見出しだけにして1か所にした（このため名前の下の余白も消え、行の間隔がそろった）

**試作で見つかった不具合と直したこと**

- 1つの分類の地図で、縮めると語が見えなくなっていた（島の段の隠し方が、分類が1つの時にも効いていた）→ 直した
- 全部の語の島の地図では、縮めた段で語を押すと、まずその島に寄る（2回目の押しで選ぶ）。意図した動きだが、初めての人には分かりにくいので、島の段では語を点で出さず島だけにする案もある
- ライブラリで押した分類（どの島から開くか）は URL に持っていない。戻ると全部の島から開く。URL（g= と同じ所）に持たせる
